1. Introduction et vue d'ensemble

1.1 Objectif de ce document

Ce document décrit le fonctionnement du site internet du club TBK : ses pages, ses fonctionnalités, le système de comptes et de droits d'accès, ainsi que la structure de la base de données qui les alimente. Il s'adresse aux membres du bureau qui administrent le site au quotidien et sert de référence en cas de reprise en main ou de passation.

1.2 Architecture générale

Le site est un site statique (HTML / CSS / JavaScript), hébergé gratuitement sur GitHub Pages. Il n'y a pas de serveur applicatif : toute la logique métier (comptes, données, sécurité) est gérée par Supabase, une plateforme qui fournit une base de données PostgreSQL, un système d'authentification, et un système de règles de sécurité au niveau des lignes (Row Level Security).

Le navigateur communique directement avec Supabase via une clé publique ("anon key"), sans intermédiaire serveur. La sécurité ne repose donc pas sur le fait de cacher des pages, mais sur ces règles définies en base : une page peut être techniquement ouverte par n'importe qui, mais les données qu'elle affiche restent filtrées selon les droits de la personne connectée.

Contacter le club par email : une icône ✉️ dans le bandeau du haut, présente sur toutes les pages du site, ouvre le client email du visiteur avec l'adresse "Email de contact du club" (réglable dans Administration → Paramètres du site) déjà renseignée en destinataire. N'envoie rien automatiquement — la personne doit valider l'envoi depuis son propre client email.

Section "Tournoi" de la page d'accueil : entièrement dynamique, à partir du tournoi actuellement en cours. Nom et date du tournoi, compte à rebours, bouton "S'inscrire au tournoi" et QR code pointent tous automatiquement vers tournoi-inscription-publique.html (voir 6.3bis). Si aucun tournoi n'est en cours, un message "Aucun tournoi n'est ouvert aux inscriptions pour le moment" s'affiche à la place. Le bouton "Voir le tournoi du…" tout en haut de la page (bandeau d'accueil) affiche lui aussi automatiquement la date du tournoi en cours.

Lien Facebook : un bouton "Notre groupe Facebook" (https://www.facebook.com/groups/3826450300980984), à côté du bouton "Voir le tournoi du…" tout en haut de la page d'accueil, ouvre le groupe du club dans un nouvel onglet.

1.3 Services externes utilisés

  • GitHub Pages — hébergement du site (gratuit, fichiers statiques).
  • Supabase — base de données, authentification, sécurité.
  • Google Calendar API — pour la page Agenda du club (lecture/écriture des événements, via connexion OAuth de l'administrateur).
  • api.qrserver.com — génération du QR code d'inscription sur la page d'accueil.

1.4 Grandes familles de fonctionnalités

  • Le site vitrine public (présentation du club, tournoi à venir, forum des associations, demande d'inscription).
  • La gestion des adhésions à la saison (inscriptions, cotisations, validation par le bureau).
  • La gestion complète des tournois (inscriptions, poules, émargement, planning, phases finales).
  • L'administration du site (comptes, droits d'accès, paramètres).
  • L'agenda du club, relié à Google Calendar.

2. Comptes et système de profils

2.1 Se connecter

La connexion se fait sur la page "Connexion" (membres.html), accessible depuis le bandeau du haut sur toutes les pages. Deux façons de s'identifier : avec une vraie adresse email, ou avec un simple nom d'utilisateur (un email technique invisible est généré automatiquement).

L'inscription est libre. Par défaut, un nouveau compte reçoit le profil "Visiteur", qui ne donne accès à aucune page protégée. C'est un membre du bureau ou l'administrateur qui doit ensuite lui attribuer le bon profil.

Un lien "Mot de passe oublié ?" sous le formulaire de connexion permet à tout utilisateur de demander lui-même un email de réinitialisation, sans passer par un administrateur — fonctionne uniquement pour les comptes créés avec une vraie adresse email.

2.2 Le système de profils configurables

Plutôt que des rôles figés dans le code, le site utilise des profils entièrement configurables depuis l'administration. Un profil est composé d'une clé technique, d'un nom affiché, et d'une liste de pages autorisées.

2.3 Profils recommandés pour un club

  • Visiteur (par défaut) — aucun accès particulier.
  • Membre — accès à l'espace membres (annonces).
  • Bureau — validation des inscriptions saison, gestion des annonces, et éventuellement gestion des tournois.
  • Administrateur tournoi (tournois_admin) — création/suppression des tournois, types de compétition.
  • Gestion tournoi (tournois_gestion) — organisation des tournois au quotidien, sans droit de suppression.
  • Émargement (tournois_emargement) — accès limité à la feuille d'émargement.
  • Admin — tous les droits, y compris l'administration du site.

2.4 Gestion des utilisateurs

Depuis Administration → Utilisateurs, un administrateur peut changer le profil de n'importe quel compte, envoyer un email de réinitialisation de mot de passe (comptes email uniquement), ou supprimer le profil d'un utilisateur (celui-ci perd alors tout accès au site, mais son compte de connexion technique reste géré depuis Supabase). Un système d'invitations permet de pré-attribuer un profil à un email avant même la création du compte. La liste est triée par ordre alphabétique d'identifiant.

2.5 Supprimer un compte complètement ou réinitialiser un mot de passe (via Supabase)

Pourquoi cette étape manuelle est nécessaire : pour des raisons de sécurité, le site (qui tourne entièrement dans le navigateur) n'a jamais accès à la clé secrète qui permettrait de supprimer un compte de connexion ou de fixer directement le mot de passe d'un autre utilisateur. Le bouton "Supprimer" d'admin.html ne retire donc que le profil (les droits d'accès) — pas le compte de connexion lui-même. Concrètement, si vous supprimez un profil puis essayez de recréer un compte avec le même email ou nom d'utilisateur, vous obtiendrez l'erreur "User already registered" tant que l'ancien compte de connexion existe encore.

Pour supprimer un compte complètement (connexion incluse) :

  1. Dans Supabase, menu ☰ → Authentication → Users.
  2. Recherchez l'email ou l'identifiant technique de la personne (ex. "nomutilisateur@tbk-club.interne" pour un compte créé par simple nom d'utilisateur).
  3. Cliquez sur le menu ⋮ à droite de la ligne correspondante → "Delete user", puis confirmez.

Pour réinitialiser le mot de passe de n'importe quel compte (y compris les comptes par nom d'utilisateur, pour lesquels le bouton de réinitialisation par email d'admin.html ne fonctionne pas) :

  1. Dans Supabase, Authentication → Users → cliquez sur le compte concerné.
  2. Dans le panneau qui s'ouvre, bouton "Reset password" : permet de définir directement un nouveau mot de passe, sans passer par un email.

Ces deux actions restent réservées au titulaire du projet Supabase (pas à n'importe quel administrateur du site) : c'est un accès distinct, plus large, que celui donné par le profil "administration".

3. Pages publiques du site

3.1 Page d'accueil (index.html)

Accessible à tous sans connexion : présentation du club, compte à rebours vers le tournoi à venir, affiche du forum des associations, QR code et lien vers le formulaire public de demande d'inscription.

Section "Le club" entièrement paramétrable (voir 7.2) : le petit texte au-dessus du titre, le titre lui-même, et les cartes (Badminton, Tennis de table, Vie associative...) sont tous modifiables depuis Administration — pas de nombre de cartes figé, l'administrateur peut en ajouter, modifier, supprimer ou réordonner autant que voulu.

3.2 Demande d'inscription publique (inscription-publique.html)

Formulaire accessible sans connexion. Les champs administratifs (WhatsApp, statut de paiement, santé, date de certificat) ne sont volontairement pas proposés : ils sont réservés au bureau, complétés au moment de la validation. Chaque demande arrive avec le statut "En attente".

4. Espace membres

Page réservée aux comptes ayant le droit "espace_membres" : affiche les annonces du club sous forme de fil d'actualité. Les comptes ayant le droit "annonces" (par défaut : admin et bureau) voient en plus un formulaire de publication au-dessus du fil, permettant de créer, modifier ou supprimer des annonces directement depuis le site.

  • Auteur et date sur chaque annonce et chaque commentaire, avec avatar (initiales).
  • Commentaires en fil de discussion indenté : tout membre peut commenter une annonce et répondre à un commentaire existant (réponses imbriquées).
  • Suppression individuelle : chaque personne peut retirer ses propres annonces/commentaires ; le bureau/admin peut tout retirer, pour la modération.
  • Réactions 👍 like, 👎 dislike, ❤️ coup de cœur, sur une annonce ou un commentaire — une seule réaction active par personne et par élément, avec compteur.
  • Pièces jointes (image ou fichier) sur une annonce comme sur un commentaire, stockées dans un espace privé réservé aux membres.
  • Plier/déplier les commentaires : bouton "💬 X commentaires ▼/▲" par annonce, affichage compact par défaut.
  • Tri du plus récent au plus ancien, en haut du fil.

Toute personne connectée, quel que soit son profil (même un simple visiteur), voit aussi une section "Mon compte" pour changer son mot de passe, et — si une inscription saison lui est reliée — une section "Mes informations" affichant sa saison, son statut, sa catégorie, sa pratique, sa cotisation, la validité de son certificat médical, ainsi que son numéro de téléphone, son adresse, son email et sa date de naissance (tels que renseignés sur son inscription).

5. Inscriptions à la saison (inscriptions.html)

5.1 Principe général

Deux façons d'alimenter la liste : saisie directe par un membre du bureau connecté (automatiquement marquée "Validée"), ou demande soumise via le formulaire public (statut "En attente" jusqu'à validation).

À droite du titre "Inscrits — [saison]", un petit résumé en police réduite rappelle en direct la répartition par sport et par catégorie : nombre de Bad, de Ping (les personnes pratiquant les deux sont comptées dans les deux), de Jeunes et d'Adultes.

Doublon nom + prénom bloqué : impossible de créer une nouvelle inscription (nom et prénom) déjà existante pour la même saison — vérifié avant l'enregistrement, aussi bien depuis le formulaire public que depuis la saisie directe par le bureau. Ne s'applique pas à la modification d'une inscription déjà existante.

5.2 Champs de l'inscription

Champs fixes : Nom, Prénom, Catégorie (Jeune / Adulte), Bad/Ping, UFOLEP/FSGT, Membre Bureau, Cotisation.

Champs personnalisables (configurables par l'administrateur) : WhatsApp, Cotisation payée, Santé, Date certificat, Téléphone, Adresse, Email, Date de naissance, Commentaire. Un administrateur peut ajouter, modifier ou supprimer ces champs à tout moment (texte, nombre, date, oui/non, liste de choix).

5.3 Calcul automatique de la cotisation

  • Adhésion club adulte : 40 € par défaut
  • Adhésion club enfant : 30 € par défaut
  • Supplément double licence (Bad + Ping) : +10 € par défaut
  • Supplément UFOLEP / FSGT : +20 € par défaut
  • Réduction membre du bureau : −10 € par défaut

Recalculé automatiquement à chaque changement, mais modifiable manuellement avant l'enregistrement.

5.4 Validation par le bureau

Seuls les profils dont la clé est exactement "bureau", ou un profil ayant accès à l'administration, peuvent valider une demande. La validation enregistre qui l'a validée et à quelle date. Un badge apparaît automatiquement dans le bandeau, sur toutes les pages, pour les profils bureau et admin, dès qu'au moins une demande est en attente ou en éléments demandés.

Inscription saisie directement par le bureau (formulaire principal, pas le formulaire public) : automatiquement validée uniquement si les conditions de validation sont réellement réunies au moment de la saisie (cotisation payée + certificat valable) ; sinon, elle reste "En attente" comme n'importe quelle autre demande, pour éviter de valider par erreur un dossier incomplet.

Annuler une validation : un bouton "Annuler la validation" apparaît sur toute inscription déjà validée, pour la repasser "En attente" en cas d'erreur.

Où se trouvent ces actions ? Depuis la simplification de l'affichage, la ligne d'une personne dans le tableau ne montre plus que "Modifier" et "Supprimer" — Valider/Annuler la validation, Certificat, Rattachement du compte, et Envoyer un email de relance se trouvent tous regroupés dans un panneau "Actions pour cette inscription", qui apparaît sous le formulaire dès qu'on clique sur "Modifier" une personne. Ce panneau se met à jour en direct pendant la saisie : dès que les conditions de validation sont réunies (ou cessent de l'être), le bouton "Valider" apparaît ou disparaît immédiatement, sans qu'il soit nécessaire d'enregistrer d'abord.

5.5 Colonnes affichées

Un administrateur choisit quelles colonnes apparaissent dans le tableau des inscrits (la colonne "Nom" est toujours visible).

Couleurs de ligne : bleu clair pour la catégorie Jeune, orange clair pour Adulte, vert dès que l'inscription est validée (prioritaire sur la couleur de catégorie). Légende rappelée au-dessus du tableau.

5.6 Conditions requises pour valider une demande

Le bouton "Valider" n'est activable que si 3 conditions sont réunies : le champ Cotisation payée est renseigné et différent de "Non" (peu importe la casse — utile si ce champ liste un mode de paiement plutôt qu'un simple Oui/Non), le champ Santé est différent de "En Attente", et le certificat médical est valable (voir 5.8 — pas seulement renseigné). Sinon, le bouton reste visible mais grisé, avec le motif précis affiché au survol (ex. "cotisation non payée" ou "certificat médical expiré (valable 3 ans et 1 mois pour la catégorie Adulte)"). Le bouton "Valider" reste accessible aussi bien sur une inscription "En attente" que "Éléments demandés" — seule une inscription déjà validée ne le propose plus.

5.7 Notification des demandes en attente

Pour les profils "bureau" et "admin", un badge "X demande(s) en attente" apparaît automatiquement dans le bandeau du site, sur toutes les pages, dès qu'au moins une inscription a le statut "En attente" ou "Éléments demandés". Un clic dessus mène directement à la page Inscriptions.

Mise à jour en direct : ce badge se recalcule automatiquement dès qu'une inscription est ajoutée, modifiée ou supprimée par n'importe qui sur le site (par exemple une nouvelle demande soumise via le formulaire public), sans qu'aucun rechargement de page ne soit nécessaire — y compris pour d'autres membres du bureau déjà connectés au même moment sur une autre page. Le badge disparaît de lui-même une fois qu'il n'y a plus de demande en attente.

5.8 Statut "Éléments demandés"

En complément de "En attente" et "Validée", une inscription passe automatiquement au statut "Éléments demandés" dès qu'un email de relance (cotisation manquante, certificat médical attendu, QS Sport attendu, ou le modèle combiné) est envoyé pour cette personne — à l'exclusion du modèle "Bienvenue", qui ne change pas le statut. Ce statut permet de distinguer en un coup d'œil les demandes déjà relancées de celles qui n'ont encore jamais été contactées. Une fois les éléments manquants fournis et vérifiés, la validation se fait normalement via le bouton "Valider".

5.9 Photo et durée de validité du certificat médical

Sur chaque demande, un bouton "📷 Certificat" ouvre l'appareil photo du téléphone (ou la galerie sur ordinateur) et envoie la photo dans un espace de stockage privé et sécurisé, lié automatiquement à cette inscription. Un bouton "Voir le certificat" génère un lien de consultation temporaire (2 minutes) à chaque demande — le fichier n'est jamais rendu public. Un bouton "Supprimer le certificat" permet de le retirer définitivement si besoin.

Durée de validité, selon la catégorie (calculée à partir de la date réelle du certificat, saisie dans le champ dédié — pas la date d'envoi de la photo) :

  • Catégorie Adulte — certificat valable 3 ans et 1 mois.
  • Catégorie Jeune — certificat valable 1 an (renouvellement annuel obligatoire).

Le statut affiché à côté de la photo ("valable jusqu'au…") tient compte de cette règle, avec un avertissement dès que l'échéance approche (30 jours) ou est dépassée. Cette même règle s'applique sur membres.html (section "Mes informations").

Ouverture de l'onglet de consultation : le lien signé s'ouvre dans un nouvel onglet créé dès le clic (avant même la récupération du lien), plutôt qu'après — sur certains navigateurs, notamment mobiles, ouvrir un onglet après un appel réseau est traité comme un pop-up et bloqué silencieusement, sans aucun message d'erreur visible. Si "Voir le certificat" ne semble rien faire pour une personne en particulier, vérifiez en second lieu, dans Administration → Profils, que son rôle dispose bien du droit de page "Inscriptions".

Photos au format HEIC (iPhone) : par défaut, un iPhone enregistre ses photos au format HEIC — or ce format ne s'affiche correctement que dans Safari, et apparaît cassé dans tous les autres navigateurs (Chrome, Firefox, la plupart des navigateurs Android). Le site convertit désormais automatiquement toute photo HEIC en JPEG dans le navigateur, juste avant l'envoi — que ce soit pour le certificat médical ou pour une photo d'article boutique — pour que la photo reste consultable par tout le monde, quel que soit son navigateur. Cette conversion ne s'applique qu'aux nouveaux envois : une photo déjà envoyée au format HEIC avant cette mise à jour resterait cassée pour les autres et devrait être renvoyée pour être corrigée.

5.10 Affichage optimisé pour mobile

Sur petit écran, le tableau des inscriptions devient une liste de fiches compactes : seul le nom et le prénom sont visibles. Un tap sur une fiche la déplie verticalement, affichant chaque information avec son libellé, suivie des boutons d'action empilés pleine largeur — bien plus lisible qu'un tableau large à faire défiler horizontalement. Sur grand écran, l'affichage reste un tableau classique, avec les boutons d'action regroupés en ligne compacte.

5.11 Rattachement de l'espace membre (automatique et manuel)

Quand une inscription est validée, le site relie automatiquement l'inscription au compte du site de la personne (même adresse email) et l'élève au profil "membre" — jamais de rétrogradation si elle a déjà un profil supérieur (bureau, admin).

  • Si la personne a déjà un compte au moment de la validation : rattachement et élévation immédiats.
  • Si elle n'en a pas encore : le rattachement se fait automatiquement le jour où elle crée son compte avec la même adresse email, sans action supplémentaire de personne.
  • Aucun compte de connexion n'est créé à la place de la personne — ce serait techniquement impossible sans clé secrète serveur, et pas souhaitable : la personne doit toujours choisir elle-même son mot de passe.
  • Bouton "Relier automatiquement les comptes existants" sur la page Inscriptions : rattrapage ponctuel pour les inscriptions déjà validées avant la mise en place de cette fonctionnalité.

Rattachement manuel — mode plus simple, ne dépendant pas d'une correspondance par email : sur chaque demande, le bureau/admin peut choisir un compte existant dans une liste déroulante et cliquer "Rattacher" (élève aussi le profil à "membre"). Un bouton "Délier" permet d'annuler un rattachement fait par erreur.

Une fois relié (automatiquement ou manuellement), sur membres.html, la personne voit ses informations d'inscription (saison, statut, catégorie, pratique, cotisation, validité du certificat médical) directement sous "Mon compte", avant les annonces — uniquement les siennes, jamais celles des autres.

Icône de liaison : en bout de ligne du tableau des inscrits, une icône 🔗 grisée apparaît pour toute personne non reliée à un compte — repérage rapide, sans avoir à ouvrir chaque fiche. Rien ne s'affiche pour une inscription déjà reliée.

5.12 Filtres par colonne (PC uniquement)

Une ligne de filtres texte apparaît sous les en-têtes du tableau des inscrits : tapez dans n'importe laquelle pour ne garder que les lignes correspondantes (filtrage instantané, insensible à la casse, sans recharger la page). Plusieurs filtres peuvent être combinés en même temps.

Limite connue : sur mobile, l'en-tête du tableau (et donc la ligne de filtres) est masqué au profit du motif de fiches dépliables — les filtres par colonne ne sont donc disponibles que sur ordinateur pour l'instant.

5.13 Envoyer un email de relance

Chaque inscription ayant une adresse email renseignée affiche un menu déroulant + un bouton "Envoyer" dans ses actions. Le modèle le plus pertinent est pré-sélectionné automatiquement selon l'état de la demande (cotisation non payée, certificat attendu, ou inscription validée), mais reste modifiable avant l'envoi.

  • Ouvre le client email de la personne connectée (mailto), avec le destinataire, le sujet et le corps du message déjà remplis — comme pour le bouton de contact du bandeau (voir 1.2), rien n'est envoyé automatiquement : il faut valider l'envoi depuis son propre client email.
  • L'adresse email de contact du club (Administration → Paramètres du site) est automatiquement mise en copie (Cc) de chaque relance envoyée, pour que le bureau garde une trace de l'échange.
  • 5 modèles disponibles : Cotisation manquante, Certificat médical attendu, QS Sport attendu, Cotisation + document santé manquants (relance combinée quand les deux manquent à la fois), Inscription validée (bienvenue).
  • Important sur le mot de passe : le modèle "Inscription validée" ne peut pas "rappeler" un mot de passe — c'est techniquement impossible pour n'importe quel système, les mots de passe n'étant jamais stockés en clair. Il invite donc la personne à créer son compte (si elle n'en a pas) ou à utiliser "Mot de passe oublié" (si elle l'a perdu).
  • Quel document de santé demander ? déterminé automatiquement : catégorie Jeune → toujours un certificat médical neuf (exigé chaque année, jamais de QS Sport pour un mineur) ; catégorie Adulte → certificat neuf si aucun certificat n'a jamais été renseigné, ou si le certificat existant a plus de 37 mois (expiré) ; dans les autres cas (certificat existant encore dans sa fenêtre de validité), un simple QS Sport suffit pour la saison. Le modèle combiné utilise la variable {document_sante} pour préciser automatiquement lequel des deux est concerné.
  • Inscription pleinement finalisée ("Validée_") : dès que le mail "Inscription validée (bienvenue)" a été envoyé ET que l'inscription est reliée à un compte (voir 5.11), le badge de statut affiche "Validée_" (avec un tiret bas) plutôt que "Validée" — une façon de repérer en un coup d'œil les dossiers réellement clos, par opposition à une validation "à sec" pas encore suivie d'effet. Annuler la validation réinitialise ce marqueur.

5.14 Modèles d'emails (configuration, profil admin)

Dans la section Configuration de cette page, le contenu (sujet + corps) des 5 modèles d'emails ci-dessus est entièrement personnalisable. Variables disponibles, remplacées automatiquement à l'envoi : {prenom}, {nom}, {montant} (cotisation attendue), {email} (adresse de la personne), {url_site} (adresse du site), {document_sante} (résout en "un certificat médical" ou "le questionnaire de santé (QS Sport)" selon la règle décrite en 5.12).

5.15 Envoi groupé par critères (profil admin)

Section réservée aux administrateurs (accès contrôlé à la fois côté affichage et côté branchement des actions), au-dessus du tableau des inscrits. Permet de filtrer les inscriptions de la saison sur plusieurs critères combinés à la fois : sport (Bad, Ping, ou les deux — "Bad" et "Ping" incluent aussi les personnes pratiquant les deux), catégorie (Adulte/Jeune), statut de la cotisation (payée/non payée), et validité du certificat médical/QS Sport (valable ou expiré/non renseigné, selon la même règle qu'en 5.9).

Le bouton "Filtrer" affiche la liste des inscriptions correspondantes (nom, email, statut), avec deux façons d'agir :

  • "Envoyer" par ligne : relance individuelle, utilisant le modèle d'email choisi dans le menu déroulant au-dessus. Chaque envoi reste un lien mailto individuel (voir 5.13) — pas d'envoi groupé automatique en un seul clic, mais un parcours rapide ligne par ligne avec le même modèle pré-appliqué à chacune. Les inscriptions sans adresse email renseignée apparaissent dans la liste mais sans bouton d'envoi.
  • "✉️ Envoyer la liste par email" : un seul email récapitulatif (et non une relance individuelle) listant toutes les inscriptions correspondant au filtrage. Un lien mailto ne pouvant contenir que du texte brut (aucune mise en forme HTML), la lisibilité est obtenue par une structuration soignée du texte : bandeau de titre, rappel des filtres et de la date d'extraction, regroupement par catégorie (Adultes / Jeunes) avec un sous-total par groupe, une icône par statut (✅ validée, 🟠 éléments demandés, ⏳ en attente), et l'email de chaque personne sur sa propre ligne. Destinataire pré-rempli avec l'adresse de contact du club (modifiable avant envoi, comme n'importe quel mailto). Sur un filtrage très large (plus de 30 résultats), un avertissement rappelle que certains clients email peuvent tronquer un message très long.

5.16 Filtres par colonne : listes déroulantes

Les filtres par colonne (5.12) proposent désormais une liste déroulante avec les valeurs réellement possibles, plutôt qu'un champ texte libre, pour toute colonne à choix limité : Statut, Catégorie, Bad / Ping, UFOLEP / FSGT, Membre Bureau, et tout champ personnalisé de type "Liste" ou "Oui/Non". Les colonnes à valeurs trop nombreuses pour une liste (Nom, Cotisation, Commentaire, dates…) restent en texte libre.

5.17 Suivi de la dernière modification

Chaque inscription enregistre automatiquement qui l'a modifiée en dernier et à quelle date — quelle que soit l'origine du changement (formulaire, validation, envoi d'un email de relance qui fait évoluer le statut...). Cette information est visible en haut du panneau "Actions pour cette inscription" (voir 5.4), et peut aussi être ajoutée comme colonne du tableau depuis "Colonnes affichées" (5.5).

6. Gestion des tournois

Le module le plus riche du site : configuration, collecte des inscriptions, répartition en poules, émargement le jour J, suivi des matchs de poule, planification en temps réel, puis phases finales.

6.1 Un seul tournoi actif à la fois

Le site ne gère qu'un tournoi "en cours" à la fois — garanti au niveau de la base de données. Toutes les pages de gestion du jour J chargent automatiquement ce tournoi actif, sans sélecteur à utiliser.

  • Création — un nouveau tournoi devient automatiquement le tournoi actif ; bloquée si un tournoi est déjà actif. Ne touche jamais aux données des tournois précédents (aucune suppression croisée) : chaque tournoi garde ses propres équipes, matchs, scores.
  • Clôture — un tournoi actif peut être clôturé une fois terminé. Ses données restent en base, mais deviennent non modifiables : le bouton "Modifier" (nom, cotisation, terrains, liste des compétitions) disparaît tant que le tournoi reste clôturé.
  • Réactivation — possible si aucun autre tournoi n'est actif ; redonne accès à la modification.
  • Consultation d'un tournoi clôturé — des liens "Consulter les poules" et "Consulter la finale" apparaissent sur chaque tournoi clôturé, ouvrant poules.html/phase-finale.html sur ce tournoi précis (au lieu du tournoi actif par défaut) — ces deux pages étant déjà uniquement consultables, aucune donnée n'y est modifiable. Le titre de la page précise "(tournoi clôturé)" pour éviter toute confusion avec le tournoi en cours. Les autres données (équipes, émargement, courses, bénévoles) d'un tournoi clôturé restent en base mais ne sont pas consultables depuis le site une fois clôturé.

6.2 Page Tournois (tournois.html)

Types de compétition : catalogue réutilisable (Simple Homme, Double Dame…), géré par "Tournois - Administration". Chaque type a un format (simple ou double) déterminant le nombre de joueurs demandé à l'inscription.

Création d'un tournoi : nom, cotisation, nombre de terrains, date du tournoi (facultative, à côté du nombre de terrains — affichée sur la page d'accueil et utilisée pour le compte à rebours), et une ou plusieurs compétitions avec leur nombre de poules et de participants par poule. La suppression est réservée à "Tournois - Administration".

6.3 Inscriptions au tournoi (tournoi-inscriptions.html)

Accessible via le droit "Tournois - Administration"/"Tournois - Gestion", ou via le droit dédié "Tournois - Inscriptions" (permet de déléguer uniquement la gestion des équipes et des poules, sans donner accès aux autres pages tournoi comme la planification ou l'émargement).

Pour chaque équipe : Nom et Club par joueur (un en simple, deux en double).

  • Affectation aux poules — encadrement visuel par poule, compteur d'équipes (ne comptabilise que les équipes validées, voir 6.3bis).
  • Tête de poule — une seule par poule, garantie en base ; toujours affichée en premier dans la liste de sa poule.
  • Échange entre poules — direct si la poule cible a de la place, sinon échange obligatoire avec une équipe de cette poule.
  • Compétition complète — les nouvelles inscriptions sont bloquées automatiquement dès que la capacité (en équipes validées) est atteinte.
  • Bouton "Répartir automatiquement en poules" pour une distribution équilibrée en un clic.

6.3bis Inscription publique au tournoi et validation (tournoi-inscription-publique.html)

Accessible sans connexion — page ouverte à tous (joueurs extérieurs au club inclus), accessible via un lien ou un QR code affiché sur la page d'accueil du site (voir 1.2). Chaque équipe se déclare elle-même : coordonnées de la personne qui fait la demande (email et téléphone, pour la recontacter et l'informer par la suite), choix de la compétition (le formulaire s'adapte automatiquement en simple/double selon son format), puis pour chaque joueur — nom, prénom, club, niveau (Débutant / Intermédiaire / Confirmé), et affiliation fédérale (Oui/Non). Une demande soumise via ce formulaire démarre toujours au statut "En attente" — jamais directement validée.

Validation par l'organisation (droits "Tournois - Administration" ou "Tournois - Gestion") : sur tournoi-inscriptions.html, une section "🟠 Demandes en attente" regroupe les demandes à traiter — coordonnées du demandeur visibles dans une colonne dédiée — avec un bouton "Valider" (la demande rejoint alors le tableau normal des équipes, avec ses données de niveau/Fédé visibles au survol) et un bouton "Refuser" (la demande bascule dans une section "⛔ Demandes refusées", d'où elle peut être remise en attente en cas d'erreur). Les équipes saisies directement par le bureau via le formulaire habituel de cette page restent automatiquement validées, comme auparavant.

Email de confirmation : au moment de valider une demande, si un email a été renseigné par le demandeur, une confirmation d'envoi est proposée ("Envoyer un email de confirmation à [adresse] ?") — un lien mailto pré-rempli s'ouvre alors dans le client email de la personne connectée, qui valide l'envoi elle-même (rien n'est envoyé automatiquement). Un bouton "Renvoyer confirmation" reste ensuite disponible sur l'équipe validée, dans le tableau normal, pour un nouvel envoi si besoin.

6.4 Émargement (emargement.html)

Bandeau du haut fixe : cotisation, recherche instantanée, compteur de présents / inscrits, montant réglé — recalculés en direct.

L'émargement se fait par joueur (et non par équipe) : chaque joueur d'un double a ses propres cases Présent / Absent / Cotisation payée. Par défaut, chaque joueur est "absent" et "non payé" à l'inscription. Nom et club restent modifiables sur cette page. Un filtre permet d'afficher uniquement les équipes avec au moins un absent.

6.5 Courses du tournoi (courses.html)

Suivi des achats effectués pour le tournoi (boissons, collations, lots…) : ajout/modification/suppression d'un article (libellé, quantité, prix unitaire), avec un total automatique en bas de liste. Réservée aux profils Tournois (Administration, Gestion, ou le droit dédié "Tournois - Courses/Achats"). Nécessite un tournoi en cours.

Le prix unitaire accepte une valeur négative, pour enregistrer une réduction (ex. "-5,00 €" sur une ligne dédiée) — le sous-total et le total s'ajustent alors automatiquement ; une ligne au sous-total négatif s'affiche en rouge pour la repérer d'un coup d'œil.

6.6 Phase Poule et classement (poules.html)

Accessible sans connexion — page de consultation ouverte à tous, avec filtres compétition/poule. Classement recalculé en direct.

  • Un match se joue en 2 sets gagnants (jusqu'à 3 sets).
  • Match gagné : 3 points. Match perdu (mais joué) : 1 point.
  • Classement trié par : Points × 1000 + (différence de sets) × 100 + différence de points marqués (valeur visible au survol du numéro de classement). Avant le début du tournoi (tout le monde à égalité), la tête de poule s'affiche en premier ; dès les premiers résultats, l'ordre reflète le classement réel.

Les matchs de chaque poule sont masqués par défaut (bouton "Afficher les matchs"). Sur mobile, chaque ligne (classement ou match) se déplie au tap pour révéler les détails, comme sur les autres tableaux du site.

6.7 Planning (planning.html)

Page de pilotage du tournoi le jour J.

Réglages : heure de début, rotation (20 min par défaut), temps minimum de repos entre deux matchs — modifiables et enregistrés automatiquement. Durée moyenne des matchs calculée en direct.

Générer / régénérer tout le planning : réservé au profil administrateur. Un seul bouton régénère l'intégralité du planning pour tout le tournoi (toutes les compétitions à la fois) : efface définitivement tous les matchs de poule ET de phase finale existants (scores déjà saisis inclus), puis reconstruit tout depuis zéro.

QR codes d'accès public : sous "Heure de début", deux QR codes permettent d'accéder directement, sans connexion au site, à Phase Poule et à la Phase finale — pratiques à afficher sur place (écran, affiche imprimée) pour que les participants suivent l'avancement en direct depuis leur téléphone.

Ordre des rencontres au sein d'une poule : les matchs sont générés selon un calendrier "round-robin" (méthode du cercle, utilisée classiquement dans tous les sports pour ce besoin) plutôt qu'un simple ordre 1-2, 1-3, 1-4... Chaque équipe joue une fois par "journée" avant de rejouer : par exemple sur une poule de 4, les 3 journées opposent chacune 2 paires différentes, sans qu'une équipe ne joue deux fois avant que toutes les autres aient joué une fois. Fonctionne aussi avec un nombre impair d'équipes (une équipe au repos par journée).

Matchs de poule par rotation : une rotation regroupe jusqu'à autant de matchs que de terrains disponibles. Aucune équipe ne joue deux fois dans une même rotation ; chaque rotation répartit ses créneaux entre compétitions au prorata exact de leur nombre d'équipes (ex. 6 créneaux sur 9 pour une compétition deux fois plus grande qu'une autre) — une compétition ayant plus de poules ne peut plus dépasser sa part sur une même rotation, ce qui garantit un remplissage optimal (par exemple 8 rotations pleines de 9 pour 2 compétitions de 32 et 16 équipes, plutôt que des rotations creuses en fin de phase de poules). Le numéro de rotation est calculé et enregistré une bonne fois pour toutes à la génération des matchs (ou dès qu'un match de phase finale devient planifiable) : il ne change plus ensuite au fil du tournoi, même si des matchs sont lancés dans un ordre différent de celui prévu. Une fois toutes les poules terminées, la section se replie automatiquement.

Terrains : vert si libre, saumon si occupé. Un match n'est "lançable" que si les deux équipes sont libres et présentes, et qu'un terrain est disponible (bouton "Lancer" grisé sinon, motif au survol). Le terrain se libère dès qu'un score complet est saisi.

Avertissement de repos insuffisant : une confirmation s'affiche si une équipe a terminé son match précédent depuis moins longtemps que le temps minimum configuré.

Statut des matchs : Non lancé, En cours, Terminé (lignes grisées, scores restant modifiables). Équipe gagnante mise en évidence en vert sur cette page et sur Poules.

Un match "En cours" peut être réaffecté à un autre terrain resté libre directement depuis la colonne Terrain (liste déroulante, sans devoir annuler puis relancer), ou son lancement peut être annulé via le bouton "Annuler le lancement" — le match repasse "Non lancé" et son terrain se libère, sans effacer les scores déjà saisis.

Saisie des scores : un clic sélectionne le contenu existant ; la touche Tabulation enchaîne les cases de gauche à droite (Set 1 équipe 1 → Set 1 équipe 2 → Set 2 équipe 1…) sans perte, même pendant le rechargement automatique — les rechargements déclenchés par la saisie sont regroupés (courte pause avant de reconstruire le tableau) pour ne jamais interrompre une saisie rapide au clavier. Chaque set (2 scores + tiret) reste toujours affiché sur une seule ligne, jamais coupé.

Bandeau du haut : réglages, terrains, top 5, et une bande plein largeur (indicateurs + filtres + génération des matchs de poule, tout sur une seule ligne) restent visibles en permanence en haut de l'écran pendant le défilement de la liste des matchs.

Affichage mobile : le tableau à colonnes classiques (dense sur PC, une ligne par match) devient une liste de fiches sur petit écran — un tap sur l'identité du match (numéro + compétition, toujours affichée sur une seule ligne, tronquée avec "…" si trop longue) déplie la fiche pour révéler poule, équipes, terrain, scores, horaires et action. Le bandeau du haut (réglages, terrains, top 5) est replié par défaut sur mobile — uniquement sur mobile, le PC reste inchangé — avec un bouton "⚙️ Réglages, terrains, top 5" pour le déplier au besoin, libérant un maximum d'espace pour la liste des matchs.

Largeur des colonnes réglable (PC) : chaque colonne a une largeur fixe par défaut (le texte trop long est tronqué avec "…" plutôt que d'élargir la colonne indéfiniment). Une petite poignée sur le bord droit de chaque en-tête permet de faire glisser pour ajuster la largeur ; un double-clic dessus revient à la largeur par défaut. Les largeurs choisies sont mémorisées dans le navigateur (pas partagées entre appareils).

6.8 Phases finales (Principale / Consolante)

Générées automatiquement dès que tous les matchs de poule d'une compétition sont terminés.

  • 1er et 2e de chaque poule → Principale ; 3e et 4e → Consolante (règle fixe).
  • Un 1er affronte un 2e d'une autre poule (jamais la sienne) ; même principe 3e/4e en Consolante.
  • Élimination directe ensuite : le vainqueur est automatiquement inséré dans le match du tour suivant dès la saisie d'un score complet.

Limite assumée : tableau propre quand le nombre de poules qualificatives est une puissance de 2 (2, 4, 8, 16…) ; sinon certaines places peuvent rester vides.

Les matchs de phase finale sont eux aussi regroupés en rotations équitables, avec une colonne "Compétition" précisant compétition, phase, et tour — nommé selon l'usage (1/8 de finale, 1/4, 1/2 finale, Finale). Principale et Consolante avancent au prorata du nombre total de matchs de leur propre tableau (et non du nombre d'équipes de la compétition) : si l'un des deux tableaux est plus petit que l'autre (cas limite ci-dessus), il reçoit proportionnellement moins de créneaux, pour que les deux terminent à peu près en même temps plutôt que l'un n'avance beaucoup plus vite que l'autre.

6.9 Synthèse Phase finale (phase-finale.html)

Accessible sans connexion — page de consultation ouverte à tous, présentant la phase finale en tableau à élimination directe classique, en colonnes par tour. Se met à jour automatiquement toutes les 20 secondes.

Traits de connexion entre chaque match et le match suivant (celui qui accueillera son vainqueur), pour mettre en évidence les enchaînements du tableau — sur la Phase Principale comme sur la Phase Consolante. Calculés à partir du vrai lien entre matchs en base (fiable même si le tableau n'est pas une puissance de 2 parfaite), ils suivent le défilement horizontal sur mobile et se réajustent automatiquement au redimensionnement de la fenêtre.

6.10 Bénévoles (tournoi-benevoles.html)

Accessible sans connexion — c'est la seule page du site conçue pour être ouverte à des visiteurs qui n'ont pas de compte (partageable largement, par exemple via un lien ou une affiche). Elle affiche les postes de bénévoles du tournoi actif.

  • Postes configurables par les organisateurs (droits "Tournois - Administration" ou "Tournois - Gestion") : nom, horaire facultatif, description facultative, nombre de places nécessaires.
  • Inscription libre, avec ou sans compte : un simple champ "Nom et prénom" suffit. Une personne connectée peut se désinscrire elle-même ; une inscription anonyme ne peut être retirée que par un organisateur.
  • Gestion complète par les organisateurs : ajout manuel d'un bénévole (même sans compte), modification du nom affiché, suppression de n'importe quelle inscription.
  • Fil de discussion propre au tournoi, ouvert lui aussi sans connexion en lecture et en écriture (avec un champ "Votre nom" facultatif pour les visiteurs anonymes) : messages, réponses indentées, pièces jointes. Les réactions (👍 👎 ❤️) restent réservées aux comptes connectés, une identité stable étant nécessaire pour appliquer la règle "une seule réaction par personne".

7. Administration du site (admin.html)

Réservée aux comptes ayant le droit "administration".

  • Mon compte — changer son propre mot de passe.
  • Paramètres du site — email de contact du club, utilisé automatiquement sur les pages publiques.
  • Page d'accueil — Section "Le club" — voir 7.2 ci-dessous.
  • Anti-pause Supabase — voir 7.1 ci-dessous.
  • Profils — création, modification des pages accessibles, suppression.
  • Utilisateurs — changement de profil, réinitialisation de mot de passe, suppression.
  • Invitations — pré-attribution d'un profil à un email.

7.1 Anti-pause Supabase (keepalive)

Le plan gratuit Supabase met le projet en pause après 7 jours sans activité (erreur "Failed to fetch" pour les utilisateurs, résolue en relançant le projet depuis le tableau de bord Supabase — voir 13.7). Un site statique comme celui-ci ne peut rien exécuter seul en arrière-plan : c'est un GitHub Actions programmé (fichier .github/workflows/keepalive.yml dans le dépôt) qui "touche" la base à intervalle régulier, sur les serveurs de GitHub.

  • La fréquence (en jours, doit rester inférieure à 7) se règle directement depuis cette page — pas besoin de toucher au fichier du workflow pour l'ajuster.
  • Le GitHub Actions s'exécute chaque jour et vérifie s'il est temps de pinguer selon cette fréquence ; le réglage est donc pris en compte au plus tard le lendemain d'un changement.
  • La date du dernier ping reçu s'affiche sous le formulaire.
  • Mise en place technique la première fois : voir 13.7.

7.2 Page d'accueil — Section "Le club"

Rend entièrement paramétrable la première section de la page d'accueil (voir 3.1), sans plus rien de codé en dur :

  • Petit texte au-dessus du titre et titre de la section — deux champs de texte libre, enregistrés en un clic.
  • Cartes (tag + texte) — ajout, modification, suppression, et réordonnancement (flèches monter/descendre) sans limite de nombre. Le contenu actuel (Badminton, Tennis de table, Vie associative) est repris tel quel comme point de départ au moment de l'activation de cette fonctionnalité, pour ne rien perdre.

8. Agenda du club (agenda.html)

Réservée pour l'instant au profil administrateur. Affiche l'agenda Google du club en vue mensuelle, avec ajout, modification et suppression d'événements directement depuis le site.

  • Connexion Google via OAuth, avec tentative de reconnexion automatique et silencieuse à chaque ouverture de page.
  • Ajout d'événement : titre, journée entière ou horaires précis, lieu, description, périodicité (aucune, quotidienne, hebdomadaire, toutes les 2 semaines, mensuelle, annuelle, avec date de fin facultative).
  • Suppression d'un événement récurrent : "Supprimer cette occurrence" ou "Supprimer toute la série".

Aucune donnée de calendrier n'est stockée sur le site : tout est récupéré et modifié en direct via l'API Google Calendar.

9. Sauvegarde des données (sauvegarde.html)

Réservée au profil administrateur. Le plan gratuit de Supabase n'incluant aucune sauvegarde automatique native, cette page permet un export à la demande : elle liste toutes les tables du modèle avec leur nombre de lignes actuel, permet d'en sélectionner une ou plusieurs, puis génère et télécharge un fichier .sql contenant les instructions nécessaires pour réinjecter les données.

  • L'ordre des tables est toujours respecté (indépendamment de l'ordre de sélection), pour éviter les problèmes de contraintes entre tables liées (ex. profils avant utilisateurs, tournois avant équipes).
  • Le fichier neutralise temporairement les contraintes pendant la réinjection, en filet de sécurité supplémentaire.
  • Restauration : ouvrir Supabase → SQL Editor, coller ou importer le contenu du fichier, exécuter.

À utiliser régulièrement (par exemple avant/après la période d'inscriptions ou un tournoi) — les fichiers générés contiennent des données personnelles de membres, à conserver dans un endroit sûr.

10. Jeu de cartes (jeu-de-cartes.html)

Accès paramétrable par profil (droit de page "jeu_cartes", pré-accordé à l'admin). Compose aléatoirement les équipes qui s'affrontent, avec un jeu de cartes numérotées de 1 à 10 — le chiffre correspond directement au numéro de terrain, ce qui minimise et fixe le nombre de terrains mobilisés selon le nombre de joueurs (ex. 16 joueurs → uniquement les terrains 1 à 4).

  • Interface pensée pour un usage à la main sur téléphone, au club : un gros bouton "Carte" fixé en bas de l'écran révèle, à chaque appui, la carte du joueur suivant en grand, avec une petite animation.
  • Les 4 joueurs qui tirent le même chiffre forment un match : la paire de cartes rouges (Cœur/Carreau) affronte la paire de cartes noires (Pique/Trèfle).
  • Reste de 2 joueurs → match en simple sur le terrain dédié. Reste de 3 → 2 matchs à 11 points à organiser entre eux. Reste de 1 → carte Joker ("passe son tour").
  • Aucune donnée stockée en base : fonctionnalité entièrement calculée dans le navigateur, à chaque session.

11. Boutique (boutique.html)

Vente d'articles en lien avec le club (textile, accessoires…) aux membres. Le paiement est suivi manuellement par le bureau — comme pour les cotisations saison — il n'y a pas de paiement en ligne sur le site.

11.1 Droits de page

  • boutique : consultation du catalogue et passage de commandes (article + taille).
  • boutique_gestion : en plus, gestion des articles (ajout/modification/suppression) et synthèse des demandes. Le profil admin y a toujours accès.

Aucun de ces droits n'est accordé par défaut à un profil existant — un administrateur doit les ajouter explicitement aux profils souhaités (ex. "membre" pour boutique, "bureau" pour boutique_gestion) depuis Administration → Profils.

11.2 Un article

Caractérisé par un nom, une description, un prix, une photo, une ou plusieurs tailles disponibles (séparées par des virgules à la saisie, ex. "S, M, L, XL" — ou une taille unique par défaut pour un article non textile), et des dates de début/fin facultatives. Un article n'apparaît dans le catalogue public que s'il est dans sa période de disponibilité ; le bureau, lui, voit tous les articles (y compris passés ou à venir) dans son panneau de gestion, avec une mention "inactif" le cas échéant.

Sur mobile, le champ photo propose le choix natif entre prendre l'article en photo directement ou choisir une image déjà enregistrée (même mécanisme que pour le certificat médical d'inscription).

Zoom sur la photo : un clic sur la photo d'un article (catalogue ou panneau de gestion) l'ouvre en plein écran, fond sombre — un clic dessus ou sur le bouton "✕" referme la vue agrandie.

Plusieurs articles à la fois : rien n'empêche un membre de commander plusieurs articles différents, ou plusieurs fois le même — chaque clic sur "Commander" crée une commande indépendante, sans limite.

Quantité : un champ numérique (1 par défaut, jusqu'à 20) permet de choisir directement le nombre d'exemplaires à commander en un seul clic sur "Commander" — équivaut à passer autant de commandes individuelles identiques (même article, même taille) d'un coup, sans avoir à répéter la manipulation. Si un flocage est demandé avec une quantité supérieure à 1, le même nom est utilisé pour tous les exemplaires ; pour des noms différents, mieux vaut commander séparément chaque exemplaire avec sa propre quantité de 1.

Option flocage : activable par article (case à cocher "Proposer un flocage" + prix, 3 € par défaut) dans le formulaire d'ajout/modification. Une fois activée, le catalogue propose un choix Oui/Non au moment de la commande ; si Oui, un champ texte demande le nom à floquer (obligatoire pour valider la commande). Le prix affiché et enregistré tient compte du supplément flocage ; la synthèse bureau indique combien d'articles, par taille, nécessitent un flocage — et rappelle la description de l'article à côté de son nom, pratique pour distinguer deux articles portant un nom proche.

11.3 Commande d'un membre

Un membre choisit un article et une taille, puis clique sur "Commander" — la demande est enregistrée immédiatement (nom de l'article, prix et taille figés au moment de la commande, pour rester cohérents même si l'article est modifié ensuite). Chaque membre retrouve l'historique de ses propres commandes dans "Mes commandes", avec possibilité d'annuler tant que la demande est encore "En attente".

11.4 Synthèse pour le bureau

  • Quantités par article et taille : tableau agrégé, pratique pour savoir combien commander de chaque taille en gros (ex. "5 × Taille M").
  • Détail des demandes : liste complète avec recherche par demandeur, description de l'article rappelée à côté de son nom, changement de statut (En attente / Confirmée / Récupérée / Annulée) et case à cocher "Payée" — mise à jour immédiate en base à chaque changement.

12. Suivi des connexions (suivi-connexions.html)

Réservée au profil administrateur. Journalise automatiquement chaque tentative de connexion au site (réussie ou échouée) : identifiant utilisé, date et heure, appareil/navigateur, et motif en cas d'échec — utile pour repérer des tentatives suspectes ou vérifier l'activité récente.

  • Compteurs en un coup d'œil : total, connexions réussies, connexions échouées.
  • Recherche par identifiant, filtres Réussies / Échouées.
  • Purge en un clic des entrées de plus de 90 jours, pour ne pas conserver ces données indéfiniment — ou purge complète de tout l'historique sans exception d'ancienneté (confirmation renforcée, action irréversible).

Note de conception : l'adresse IP n'est volontairement pas collectée (nécessiterait un service tiers externe, pour un intérêt limité sur un site de club face à la sensibilité de cette donnée).

12.1 Visites des pages sans connexion requise

Cette même page journalise aussi automatiquement les visites sur les pages accessibles à tous, sans compte : accueil, demande d'inscription publique, bénévoles, connexion/inscription, réinitialisation de mot de passe, politique de confidentialité. Répartition par page en un coup d'œil, journal détaillé (date, provenance, appareil), et purge en un clic des entrées de plus de 90 jours — ou purge complète sans exception d'ancienneté.

13.4 Principes de sécurité (RLS)

  • Chaque table sensible vérifie le profil de la personne connectée via une fonction "current_user_has_access".
  • Certaines actions (validation d'inscription, suppression de profil, écriture sur les tournois) sont réservées aux profils précis nommés dans ce document.
  • Des déclencheurs (triggers) en base garantissent certaines règles même en cas d'erreur côté site : une seule tête de poule par poule, un seul tournoi actif, blocage au-delà de la capacité, impossibilité de modifier son propre profil.
  • Le formulaire public de demande d'inscription dispose d'un droit d'écriture volontairement restreint : il ne peut créer qu'une inscription "En attente", jamais la valider lui-même.

13.5 Stockage de fichiers (Supabase Storage)

Au-delà des tables, deux espaces de stockage de fichiers privés :

  • certificats-medicaux : photos de certificats médicaux prises depuis la page Inscriptions. Accès (lecture, dépôt, suppression) réservé aux comptes ayant le droit "inscriptions". Consultation via lien temporaire (2 minutes), généré à la demande.
  • boutique-photos : photos des articles de la boutique. Lecture réservée aux comptes ayant accès à la boutique ("boutique" ou "boutique_gestion"), dépôt/suppression réservés à "boutique_gestion".

Aucune lecture publique n'est possible sur ces deux espaces — jamais via une URL permanente.

13.6 Nettoyage automatique des réactions orphelines

La table annonces_reactions pointe vers une annonce, un commentaire ou un message de tournoi sans lien de clé étrangère (elle peut viser l'une ou l'autre de ces 3 tables). Des déclencheurs SQL suppriment automatiquement les réactions correspondantes dès qu'une annonce, un commentaire ou un message de tournoi est supprimé, pour éviter toute accumulation silencieuse de données orphelines.

13.7 Mise en place de l'anti-pause Supabase (une seule fois)

Après avoir exécuté migration_keepalive.sql :

  1. Ouvrez le fichier .github/workflows/keepalive.yml du dépôt GitHub.
  2. Remplacez SUPABASE_URL et SUPABASE_ANON_KEY par les vraies valeurs (identiques à celles de js/supabase-config.js, trouvables dans Supabase → Project Settings → API). La clé "anon public" n'est pas un secret : elle est déjà visible par n'importe qui dans le code du site.
  3. Enregistrez sur la branche principale du dépôt (indispensable pour qu'un workflow programmé s'exécute).
  4. Vérifiable depuis l'onglet "Actions" du dépôt GitHub, où chaque exécution (quotidienne) et son résultat s'affichent — un déclenchement manuel immédiat y est aussi possible.
